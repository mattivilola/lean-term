# Initial experiment — 4 November 2026

**V1 decision accepted by Matti: Swift + AppKit + SwiftTerm, with CoreGraphics/CoreText.**
The Release fixture runs with both SwiftTerm renderers. Two controlled typing
runs per renderer, a Ghostty reference and a warm-up yielded 1,200 exported
samples. Output and a first memory pass were also measured. Visible-ready
startup, gated memory follow-up and the longer soak remain unfinished; they are
not prerequisites asserted as passed by this initial stack-selection exercise.

This is a small measurement fixture, not LeanTerm's initial product version or
its final interface. Do not promote these figures as initial-version app results
on leanterm.com.

## Conditions

M3 Max MacBook Pro, 36 GB RAM, macOS 27.0.1, Xcode 27.1 / Swift 6.4, AC power.
120 × 40 cells, Menlo Regular 13, opaque dark background, 10,000 scrollback lines,
120 Hz maximum Retina display, scale 2. The Metal diagnostic confirms its render
loop is enabled; CoreGraphics confirms Metal is disabled. This is an interactive
workstation, not an otherwise empty lab machine.

SwiftTerm: `309adcc28bdf0e01f6403d04616323b379fb5635`. The app was an uncommitted
initial working tree when these first measurements ran. Raw diagnostics,
environment, resolved dependencies and a binary/source manifest accompany this
report. No custom terminal engine or renderer was implemented.

## Output and memory

| Fixture | ASCII intake, median MiB/s | ANSI/Unicode intake, median MiB/s | Idle footprint, MiB | Filled footprint, MiB | Idle CPU, % of one core |
|---|---:|---:|---:|---:|---:|
| SwiftTerm Metal | 166.4 | 54.4 | Repeat needed¹ | 84.0 | Repeat needed¹ |
| SwiftTerm CoreGraphics | 192.0 | 57.7 | 49.9 | 64.5 | 0.17² |

Three approximately 10 MiB writes per corpus, identical recorded hashes and
actual terminal dimensions. These are **PTY writer-completion rates**, not
rendered throughput or typing latency. The final mixed-output marker and Unicode
text were visually observed in both renderers. The differences do not establish
an interactive-response winner.

¹ The Metal “idle” recording overlaps the beginning of output near its end. Its
raw file is explicitly marked invalid for idle comparison. Stable earlier
readings were about 62.9 MiB, and one reading during the output burst reached
273.3 MiB, before settling to the recorded 84.0 MiB. These are observations at
different phases, not a clean idle result or a comparable peak-memory test.
The workload now supports an explicit start gate to prevent this overlap.

² The sampler originally mislabeled Mach ticks as nanoseconds. All retained
counter readings were relabeled and recomputed with this Mac's actual 125/3
timebase. A 250 ms CPU workload compared the fixed sampler against Python's
process CPU clock: 0.249013 s versus 0.248912 s (ratio 1.0004). The earlier
preliminary CPU figures are superseded. Raw readings and correction notes are
preserved; the invalid Metal interval is not used to claim idle CPU.

Memory is process physical footprint; RSS is retained separately. Shell/Python
child memory is excluded. The workload's `parent_pid` can be the launching shell;
the GUI PID is recorded in each renderer's info file. Early files contain a
documented metadata correction for that name.

## Typing results and decision

All successful runs contain 200 samples. User-operated start/focus resolved the
intermittent automation issue. The complete export is `latency.csv`; summary
statistics are reproducible with `../summarize_latency.py`. The first column
matches the separately saved preflight exactly; all six columns and 1,200 numeric
samples were checked. `latency-run-map.json` preserves the untitled run mapping.

| Run | Median ms | p95 ms | Role |
|---|---:|---:|---|
| Untitled, column 1 | 42.76 | 77.65 | CoreGraphics warm-up; excluded from decision |
| Untitled, column 2 | 22.11 | 34.92 | Fresh CoreGraphics fixture |
| Metal | 34.09 | 69.63 | Metal fixture |
| Ghostty 1.3.1 | 31.00 | 58.08 | One reference-app run |
| Metal-confirm | 32.10 | 55.18 | Reverse-order confirmation |
| CG-confirm | 27.05 | 49.03 | Fresh CoreGraphics confirmation |
| Terminal.app | unavailable | unavailable | Reference-pattern/available-line calibration failed |

The initially untitled result 2 was CoreGraphics, by recorded launch sequence,
renderer diagnostics and the verified export ordering. CoreGraphics stayed ahead
of Metal in both passes, but its advantage narrowed in the confirmation. The
confirmation median difference is about 5 ms, smaller than one interval at the
display's reported 120 Hz maximum. Actual variable refresh and background load
were not independently fixed. This supports a practical initial default, not a
high-precision universal latency ranking.

Typometer 1.0.1 / Java 21 uses AWT Robot capture on this Mac; its faster native
API is unavailable here. These are synthetic OS-input-to-screen-capture timings,
**not physical key-to-photon**. Capture overhead is included. The tool required
Java compatibility options, user-granted permissions and manual window-focus
changes. Failed/unfinished calibration attempts were excluded.

Matti selected Swift/AppKit + the reusable SwiftTerm view with CoreGraphics.
The choice combines encouraging local response results, lower measured filled
footprint in the first pass and a small native integration with one primary Swift
toolchain. It avoids writing a custom renderer or adding a language bridge for
v1. **Rust was not benchmarked and is not shown to be slower.** It remains a
future option if profiling identifies a benefit worth its integration cost.
Ghostty's result describes its existing app, not a future embedded LeanTerm build.

## What is established

- The pinned reusable SwiftTerm component builds and renders the deterministic
  ASCII/ANSI/Unicode fixtures in both native rendering paths.
- The CoreGraphics fixture has lower measured filled-scrollback footprint in
  this first pass. Throughput alone cannot choose the renderer for LeanTerm.
- A clean, visually polished native interface remains a product requirement;
  this fixture does not evaluate the final design.
